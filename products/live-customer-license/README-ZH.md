# Adaptive Trading Bot Live · 客户订阅版 0.3.5

这是本机运行的真实资金软件，包含现货和 U 本位／币本位永续合约。请先完成只读检查，交易必须由你手动确认。没有收益保证，风险规则也不能保证最大亏损。

## 安装和软件许可证

1. 完整解压与你的系统对应的 ZIP。Windows x64 运行 EXE 安装器；Ubuntu／Debian x64 使用系统包安装器安装 DEB（推荐终端 `sudo apt install ./AdaptiveTradingBot-Live-Customer-0.3.5-linux-amd64.deb`）；Mac 按 Apple 芯片 arm64 或 Intel x64 选择，把 Adaptive Trading Bot Live Customer.app 移入 Applications。
2. 本版与旧自用版、Testnet 使用不同的应用及配置目录，不会自动迁移或接管旧仓位。不要让两个机器人同时操作同一个交易账户。
3. 使用购买这个实盘商品的 Whop 账号，打开订单和 Software，复制软件许可证：
   https://whop.com/adaptive-trading-bot-live/exp_1vOy7FcD1W5Xml/app/
4. 在软件窗口顶部的“Whop 软件许可证”粘贴，点击“验证许可证”。这里不能填写 Whop 商户 API Key、币安 API Key 或旧测试版许可证。
5. 授权有效后再配置自己的币安正式账户。保存或只读连接不会下单；现货与合约分别需要你输入指定确认文字并启动。

每个许可证绑定一台设备，同时仅允许一个运行会话。换机联系卖家重置；同机异常退出后可能需等待最多约 120 秒释放旧会话。许可证每 30 秒联网核验，签名授权最多 120 秒且不超过会员有效期。取消续费通常保留已生效期限，实际以 Whop 的会员状态和有效期为准。过期、撤权或无法核验会停止自动策略和本机自动追加，不会自动平仓；已经接受的交易所保护单仍需在币安核对。合约已有程序仓位保留手动平仓入口。恢复联网或续费后不会自动重启交易。

许可证仅在操作系统加密存储可用时保存；Linux 没有可用系统密钥环时只在本次会话中使用，重启需再次粘贴。币安凭据使用各市场独立的本机保险箱密码加密；不上传到 Whop 或授权服务器。

Windows 与 Mac 版本未签名，Mac 未经 Apple 公证。请核对来源和校验值；不要为此全局关闭系统安全保护。四平台构建和离线检查不代表已经验证真实账户成交；首次使用请由本人安排并核对真实账户测试。

## 现货

点击顶部“现货 / Spot”。设置或解锁至少 12 字符的本机保险箱密码，填写本人正式现货 API Key，并选择匹配的 HMAC Secret 或现货 Ed25519 PEM。可以在软件生成或找回同一个注册公钥，再在币安注册并取回相应 API Key；API Key 不是私钥。

先保存和只读连接，核对真实余额、交易对、预算、信号、实际费用和已有委托，再由本人输入 `START REAL SPOT TRADING` 并启动。既有手动持仓不会被自动接管。内置策略和外置现货 JSON 导入继续保留。只读连接及重连不会自动重新启动交易。

## 合约：基本配置

点击顶部“合约 / Futures” → 左侧“账户与合约”。

1. 设置或解锁本机合约保险箱。填写本人正式合约 API Key，HMAC Secret 或合约 RSA PEM 二选一。两个合约钱包需可读取；不需要提现权限。现货 Ed25519 PEM 不能当作本版合约 RSA PEM。
2. 选择 U 本位 USDT／USDC 永续或币本位反向永续，读取币安已有模式、杠杆与账户。读取不下单、不修改设置。
3. 选择保证金模式、杠杆、每次初始保证金占比和持仓管理方式，保存本机配置。杠杆以实际合约与账户档位为准，不自动选最大。
4. 点「保存修改后的本机配置」，在合约总览核对「本机已保存」的比例、模式与杠杆。「币安实际」显示最近一次读取的合约设置。例如本机为 102×、币安为 150× 时，停止策略，核对所选合约空仓且无待处理委托，输入 `APPLY FUTURES SETTINGS` 并点「应用所选模式和杠杆到币安」。再次只读核对，确认两处模式和杠杆一致后可启动。多资产模式只支持全仓。开启持仓共存后，其他合约的手动仓可以保留。
5. 单仓管理同时只保留一边；双向管理允许该合约一多一空，策略分别判断开仓、退出和保护。切换交易对／合约类型／交易策略需停止、空仓且无待核对委托。

本版管理一个选定永续合约，不管理季度交割、组合保证金或其他机器人／手动合约仓位。在「账户与合约」选择与币安账户一致的 U 本位资产模式，保存后点「只读核对」。只用 USDT 交易 USDT 合约时，单资产即可。希望共用多种合格抵押资产时可选多资产和全仓。币安决定哪些资产合格及其折算比例。软件显示交易所扣除持仓和挂单占用后的可用保证金，按 USDT 折算。实际委托还受每笔比例、手续费和最小订单限制。此处选择保存在本机；如需切换账户模式，请到币安 U 本位合约的资产模式设置。全仓可以涉及同类担保资产的其他可用保证金；所选初始保证金不是全仓最大损失上限。

## 启用币安双向持仓

“账户与合约”第 04 区显示实际账户单双向状态。仅选择软件的“双向管理”不会自动改变币安。

需要改变时，两个合约钱包都必须空仓，且没有普通或条件委托。本人输入 `ENABLE FUTURES HEDGE MODE`，点击“确认并启用币安双向持仓模式”。该设置同时影响 U 本位和币本位，程序会再次读取核验。没有确认文字不会修改，不会静默关闭已有双向模式。

## 保留手动仓，同时运行合约策略

默认选项「发现外部持仓时暂停」会在发现外部仓位时阻止启动。已有配置升级后沿用此选项。

1. 解锁本机配置。在「账户与合约」为机器人选择一份独立合约。例如手动持有 U 本位 BTCUSDT，可把机器人设为 U 本位 ETHUSDT。让所选合约只保留本程序能够核对的仓位和委托，包括条件单。双向模式下，多空两边也都属于这份合约。
2. 在「外部持仓」选择「允许其他合约持仓共存」，点「保存修改后的本机配置」。首次配置时使用「首次保存加密配置」。回到「合约总览」点「只读核对」。本程序只操作自己创建并核对的仓位，其他合约的仓位由你在币安管理。
3. 查看本次核对返回的可用保证金。币安若允许某部分浮盈用于开仓，这部分已体现在可用额中。浮盈回落或新增挂单都会影响后续可用额。软件仍按每笔比例、费用和合约最小下单量检查，显示正的可用额也可能达不到最小订单。日内回撤仍按账户权益衡量，手动仓的盈亏也会影响当天能否继续开新仓。如果软件无法核实当天零点的权益，新增仓位会暂停。

## 多空独立策略与手动锁仓

“合约总览”分别显示多仓、空仓的数量、入场价、保护价和强平价。内置交易规则或导入的双向 JSON 对两边分别评估；订单串行提交，两边各有自己的交易所保护单。单仓策略依旧保留冲突信号等待逻辑。

本人输入 `START REAL FUTURES TRADING` 后启动自动交易。停止后再次启动，需重新输入该确认文字。策略可以等待信号，单次预算不足最小订单时跳过该次开仓。该确认同时用于明确选择某一方向的市价平仓；“市价平多仓”和“市价平空仓”只处理该方向已核对的程序仓位。

手动锁仓流程：

1. 在“手动等量对冲／锁仓”点击“预览等量对冲（只读）”。查看要补的方向、数量、保证金和名义金额。
2. 输入 `LOCK FUTURES POSITION`，点击提交。程序停止自动交易，再次核对仓位，并在较小的一边按数量差建立反向仓。
3. 仍受初始保证金预算、可用资金、档位、最小交易量和当日停开限制。不能为了等量擅自提高杠杆或放大预算。
4. IOC 可能部分成交。界面如实显示两边数量差，不会盲目补单；再次明确预览和确认，才会尝试补剩余差额。
5. 手动锁仓后自动交易保持暂停。两边保护单继续存在；任一保护触发、手动平仓或资金费都会改变对冲状态，不能视作收益永久冻结。
6. 要恢复自动交易，先核对两边，输入真实交易确认文字，点“解除锁仓暂停状态”，然后再本人启动。解除暂停本身不平仓、不自动恢复。

## 保证金比例与每日风险

每次新开仓的初始保证金比例可选 0.01%–100%，默认 1%。例如填 10 表示以权益的 10% 计算初始保证金预算。预算还会受当前可用保证金、手续费和合约最小订单限制。两边分别占用保证金，不能把对冲后的净敞口当作不占资金。杠杆扩大名义仓位，最小交易量或资金不足时会拒绝，不擅自放大。

权益含两边未实现盈亏、实际佣金、资金费和担保币本身的价格变化。滑点已在真实成交价中体现，不重复扣一笔。每天按 UTC+8 零点分界，首次建账当日从建账时权益起算。回撤超过 20% 后，当天锁定新增多空、锁仓新增反向仓和本机自动追加；已有程序仓位仍可减仓和平仓。手动追加需本人额外确认。20% 是触发阈值，不保证最终亏损封顶。

## 逐仓保证金：实际状态与手动追加

入口在“合约” → “账户与合约”第 05 区“逐仓保证金”。

- “币安原生自动追加”按实际返回显示开启、关闭或未返回。普通逐仓本来未开启时，无需再额外关闭；未返回也不会假装显示关闭。
- 这里没有伪造的币安原生开关。若币安返回已开启，需要在币安对应持仓设置核对；本机 JSON 自动追加不能与已开启或无法核实的原生自动追加叠加运行。
- 手动追加：选择 LONG 或 SHORT，填写显示币种的追加金额，输入 `ADD ISOLATED MARGIN`，再点击“停止自动化并追加到所选逐仓持仓”。U 本位通常填 USDT／USDC，币本位填对应担保币数量，不能把 5 USDT 写成 5 BTC。
- 追加会占用更多资金，但不增加合约数量，也不作为额外充值或收益记入总权益。本版只追加，不自动移出保证金。全仓、无持仓或不属于程序的仓位不能通过此入口追加。
- 结果不明时保留原请求，只查询原保证金变动历史，不重复提交。不要同时在币安做相同方向和金额的追加来干扰核对；无法确认需人工复核。

## 本机自动追加：只由外置 JSON 决定

入口在同页第 06 区。本版没有内置自动追加触发规则。保留内置交易策略，不代表内置自动追加策略。

下载的 `example-auto-margin.json` 只展示格式，默认 `enabled:false`、金额和次数为零，不能直接花钱。用户自行填写并核对这些字段：

| 字段 | 含义 |
| --- | --- |
| id | 该份累计预算的唯一标识；同 ID 重启或重导入不清零 |
| enabled | JSON 是否允许启用；仅改为 true 仍不会自行开始 |
| market / symbol / asset | 必须与所选合约及原生保证金币种一致 |
| positionSides | LONG、SHORT 或两者 |
| trigger.liquidationDistancePercentAtMost | 标记价到交易所返回强平价的距离百分比，达到用户填写条件才考虑追加 |
| perAdditionAmount | 每次追加的原生币数量，字符串填写 |
| maxTotalAmount | 该 ID、该合约的两边合计自动追加累计预算 |
| maxAdditions | 两边合计自动追加次数上限 |
| cooldownSeconds | 两次自动追加的最短间隔，启用时至少 30 秒 |

启用步骤：先停止自动化，使用保险箱密码导入自设 JSON，核对目标、金额、预算和已用量。本人输入 `ENABLE JSON AUTO MARGIN`，点击“启用已导入的 JSON 自动追加”。如还要运行交易策略，再单独确认启动交易。两种状态都会显示在顶部，切换页面不会停止后台已启用的自动化。

重启、断线异常和系统睡眠后需重新确认。本机自动追加只在软件运行且本次明确启用时工作，不能代替交易所常驻服务。日内停开、未知请求、没有可靠强平价／保护／原生自动追加状态、资金不足、冷却期或预算耗尽时不执行。不保证来得及在强平前完成。

累计用量确认后才计入持久账本；超时不会重复追加。重复导入或修改同 ID 的参数不会清零用量，不同币种／合约也不能复用同一个 ID。另设新 ID 表示用户明确新建另一份预算，应自行核对累计投入。

## 停止、关机与异常

停止策略同时停用合约交易和本机 JSON 自动追加，但不把已有仓位自动平掉。已确认的交易所止损保留。本机止盈、追踪退出和自动追加在关机后停止。开仓与提交保护是两个请求，存在无保护间隙；止损触发和成交价都不保证。出现无法核对的委托或保护时，保留记录并立即到币安查看，需要时本人处理。

核对异常时请保留账本，到币安检查所选合约的持仓和委托。先导出 CSV 与复盘，再讨论新规则；软件不会自动向客户发消息或调用付费 AI。

配置位置：Windows `%LOCALAPPDATA%/AdaptiveSpotBot/LivePersonal`、`.../FuturesPersonal`；Linux 默认 `~/.local/share/AdaptiveSpotBot/` 下对应目录；Mac `~/Library/Application Support/AdaptiveSpotBot/` 下对应目录。仅在程序退出、原请求核对后备份整个目录。密钥加密保存在本机，不上传到 Whop 或 Cloudflare。
