# 虚拟量化交易程序：中文安装、配置和使用手册

本手册针对随源码包提供的 **v3 / adaptive / short 短周期策略**。它仅连接 Binance 现货测试网，使用虚拟资金，交易对固定为 BTCUSDT。没有实盘开关，也不包含合约、充值、提现或转账功能。

这是按明确规则运行的实验程序，不是聊天中的 AI 在每次交易前临场判断。它没有经过盈利能力验证；更频繁地检查或更复杂的条件，都不代表一定赚钱。

## 一、先选对安装方式

| 你的情况 | 应当怎么做 |
|---|---|
| 全新电脑、全新测试账户，尚无本程序持仓 | 按第二节开始安装 |
| 原电脑上的策略已经运行，只想保存或阅读源码 | 保存 ZIP 即可；不要在新目录再启动同一个账户的机器人 |
| 原电脑程序停止了，需要恢复 | 优先使用原目录和原记录，按第九节核对后恢复 |
| 想换电脑、换目录、换 API Key，或更换策略版本 | 先停止并核对原实例，再安全备份、审查迁移；不要直接把新目录当作空仓启动 |

**特别重要：锁只保护同一个本地目录。** 同一账户在另一目录、另一电脑启动第二个副本，原目录的锁无法阻止它。源码 ZIP 刻意不包含账户持仓和订单记录，它不是原账户的恢复备份。

本次源码交付本身不启动、不停止机器人，也不修改正在运行的账户。解压、查看说明、运行离线测试都不会自动开始交易。

## 二、安装运行环境并解压

1. 从 [Node.js 官方下载页](https://nodejs.org/en/download)安装 **Node.js 24.x**，使用安装程序默认提供的 npm。此包的版本要求是 `>=24 <25`。
2. 安装后重新打开 PowerShell，让它识别新的 Node.js。
3. 把源码 ZIP 解压到一个新的空文件夹，例如 `C:\QuantVirtual`。不要覆盖原来正在交易的目录，也不要放进公开共享目录。
4. 在解压后的文件夹打开 PowerShell。应当能看到 `package.json`、`scripts`、`lib`、`strategies`、`docs`、`dashboard`、`tests`。

以下命令都在**解压后的程序根目录**执行；示例目录按你的实际位置修改：

```powershell
Set-Location -LiteralPath 'C:\QuantVirtual'
node --version
npm.cmd --version
```

`node --version` 应显示 `v24.` 开头。找不到命令时，先重新打开终端、检查 Node.js 安装，不要从陌生网站下载替代运行器。

**无需 `npm install`，无需 Python、Docker、Next.js 或数据库。** 独立源码包使用 Node.js 内置功能，已经包含运行和测试所需的源码；不要照搬原开发工作区的网页构建步骤。

Windows 如果提示“无法加载 npm.ps1，因为在此系统上禁止运行脚本”，使用本手册中的 `npm.cmd` 即可。不需要管理员权限，不需要关闭系统安全策略或全局设置执行策略。

本手册以 Windows 为主。macOS / Linux 在终端进入程序根目录后，将运行命令中的 `npm.cmd` 换成 `npm`；PowerShell 专用的文件复制和路径命令不能原样照搬，创建配置时仍须先确认目标文件不存在。

### 可选：检查下载完整性

在 ZIP 所在目录执行下面的命令，把文件名替换成实际名称，再与 ZIP 旁的 `.sha256` 文件比较：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\virtual-quant-source-实际时间戳.zip'
```

解压后的 `SOURCE_MANIFEST.json` 还记录了各个源码文件的 SHA-256。校验和能检查文件字节是否发生变化，不是作者签名、无漏洞证明或收益证明。

## 三、先做完全离线的检查

```powershell
node scripts/virtual-trading.mjs --describe
npm.cmd test
npm.cmd run check
```

- `--describe`：核验并显示策略；不加载密钥、不联网、不读取账户、不下单。
- `test`：运行本地模拟数据与桩测试，不连接真实撮合账户。
- `check`：检查源码导出的白名单和模板，不生成新压缩包、不交易。

全部通过后再配置测试网。测试通过只说明被覆盖的程序行为符合测试，不代表策略盈利。

## 四、配置你自己的测试网密钥

只在 [Binance 现货测试网](https://testnet.binance.vision/)由你本人完成登录和密钥登记。**币安正式站的网页登录，并不能代替这里的 API 配置。** 不需要正式钱包密钥。

密码、验证码、API Secret 和私钥不要发给任何人，不要粘贴到聊天、策略 JSON、GitHub、看板或共享压缩包。导出包的三个凭据字段都为空，需要在自己的电脑配置。

### 方案 A：本地 Ed25519 密钥对

仅在没有现有密钥的新安装目录运行一次：

```powershell
node scripts/testnet-keygen.mjs
```

程序在 `.secrets` 中创建：

| 文件 | 用途 |
|---|---|
| `testnet-ed25519-public.pem` | 公钥；只把这个公钥的内容登记到现货测试网 |
| `testnet-ed25519-private.pem` | 私钥；只保留在本机，绝不上传或发给别人 |

脚本拒绝覆盖已有密钥文件。如果文件已经存在，不要删除后重生成来“修复连接”；先核对其是否与测试网登记的公钥匹配。

按测试网页面提供的方式登记公钥并取得 API Key。仅授予测试账户读取、现货虚拟下单所需的权限；无需提现、转账或额外接口权限。只有读取权限时，可能能看到账户，却不能完成虚拟下单。

### 创建本机配置文件：只做一次，绝不覆盖已有文件

仅对全新安装使用下面的带保护复制：

```powershell
if (Test-Path -LiteralPath '.env.testnet') {
    throw '已有 .env.testnet：停止复制，保留原凭据并先核对。'
}
Copy-Item -LiteralPath '.env.testnet.adaptive.example' -Destination '.env.testnet' -ErrorAction Stop
```

用本机文本编辑器打开 `.env.testnet`，只编辑凭据字段。下面是**格式说明，不能原样当作真实配置使用**；把占位文字替换成你自己的测试网 API Key：

```dotenv
BINANCE_TESTNET_API_KEY=这里填你自己的测试网API_KEY
BINANCE_TESTNET_API_SECRET=
BINANCE_TESTNET_PRIVATE_KEY_PATH=.secrets/testnet-ed25519-private.pem
```

Ed25519 模式中 API Secret 必须留空。相对私钥路径以程序根目录为基准；不要填公钥文件，也不要把 PEM 正文塞进路径字段。确认文件名是 `.env.testnet`，不是资源管理器隐藏扩展名后的 `.env.testnet.txt`。

### 方案 B：测试网 HMAC 密钥

若你持有测试网签发且受该测试网支持的 HMAC 密钥，可以不用生成 Ed25519。只在本机 `.env.testnet` 配置：

```dotenv
BINANCE_TESTNET_API_KEY=这里填你自己的测试网API_KEY
BINANCE_TESTNET_API_SECRET=这里填同一测试网密钥的SECRET
BINANCE_TESTNET_PRIVATE_KEY_PATH=
```

**二选一，不能同时填 HMAC Secret 和私钥路径。** 正式站 API Key、Secret、主站地址不能加入此包。程序会拒绝 `BINANCE_BASE_URL`、`BINANCE_API_KEY`、`BINANCE_API_SECRET` 这类非 Testnet 配置。

限制本机凭据和私钥的文件访问权限，避免放进多人共享或自动同步的公开位置。若凭据曾泄露，应在测试网撤销并安全更换；不要只删聊天或 Git 最新版本后继续使用。

## 五、先预览，再明确启动虚拟交易

下面两项不会创建撮合订单：

```powershell
npm.cmd run virtual:status
npm.cmd run virtual:preview
```

`status` 读取测试账户余额及 `canTrade`；它不等于机器人正在运行。`preview` 只做一次不保存交易的信号预览；需要连续行情采样时，一次预览可能显示 `WAIT` 或预热，这是正常情况。

可选的 `npm.cmd run testnet:validate` 会向测试网 **POST `/api/v3/order/test`**，检查签名和下单参数，不进入撮合引擎、不会成交；它不是纯离线检查。如果只想做只读预览，可以跳过此项。不要把这个检查误当成买入记录。

确认这是新账户首次启动，或原账户的持仓、未完成订单和原实例都已核对后，执行：

```powershell
npm.cmd run virtual:run -- --enable-testnet-orders
```

这条命令才会明确允许**测试网虚拟委托**。不带额外的 `--enable-testnet-orders` 标志会拒绝启动。保留这个前台终端，观察带时间的执行结果；不要重复打开几个窗口来催它成交。

直接使用 Node.js 的等价命令是：

```powershell
node scripts/virtual-trading.mjs --run --enable-testnet-orders
```

两种启动方式选一种，不要同时运行。不要用旧版底层启动命令绕过策略 JSON，也不要用单次试单选项制造“自动策略成交”。

## 六、单独打开只读交易看板

在**第二个 PowerShell 窗口**进入同一个程序目录，然后执行：

```powershell
npm.cmd run testnet:dashboard
```

打开 [本机交易看板](http://127.0.0.1:3001/)。它只绑定本机 `127.0.0.1:3001`，没有买卖按钮，不修改交易状态，不是公开网站。别开放公网端口，也别把带账户数据的页面部署成公共服务。

看板与机器人是两个独立进程：

- 关掉看板终端或网页，不代表机器人停止。
- 打得开网页，不代表账户刷新成功或机器人仍在运行。
- 刷新时间、活动状态、真实成交记录和持仓应一起核对。连接失败后保留的旧数值不是当前账户情况。
- `WAIT` 表示该次检查没有满足交易条件；检查次数不是成交次数。
- 图中的 SMA 参考线不是 adaptive 策略实际使用的 EMA 计算，不能仅凭图线判断它一定应该成交。

首次成功联网后可以看到测试账户、当前策略、持仓与已确认成交。源码包不含你原账户的历史记录，因此新目录不应凭空出现原机的完整历史。

## 七、全部可配置字段

权威策略文件是 `strategies/virtual-only.json`。当前完整默认值为：

```json
{
  "version": 3,
  "mode": "BINANCE_SPOT_TESTNET_ONLY",
  "strategy": "adaptive",
  "adaptiveProfile": "short",
  "symbol": "BTCUSDT",
  "interval": "1m",
  "pollSeconds": 5,
  "maxPositionUsdt": 100,
  "fastPeriod": 3,
  "slowPeriod": 8,
  "stopLossPercent": 0.15,
  "takeProfitPercent": 0.15,
  "maxHoldMinutes": 3,
  "cooldownSeconds": 10,
  "maxBuysPerHour": 60
}
```

| 字段 | 当前值 | v3 允许范围 / 含义 |
|---|---|---|
| `version` | `3` | 本手册使用 3；不要混用旧版字段 |
| `mode` | `BINANCE_SPOT_TESTNET_ONLY` | 固定，仅测试网 |
| `strategy` | `adaptive` | 此版本固定 |
| `adaptiveProfile` | `short` | v3 必填且固定为 short |
| `symbol` | `BTCUSDT` | 此启动器固定，不能换币种 |
| `interval` | `1m` | 固定的已收盘 1 分钟 K 线 |
| `pollSeconds` | `5` | 整数 5–10；目标检查间隔，不是成交间隔 |
| `maxPositionUsdt` | `100` | 数值 25–100；每轮累计买入名义金额上限，单位虚拟 USDT |
| `fastPeriod` | `3` | 整数 3–10，须小于慢均线周期 |
| `slowPeriod` | `8` | 整数 5–30 |
| `stopLossPercent` | `0.15` | 基础输入 0.1–5，单位百分比；新开仓还有下文的短模式限幅 |
| `takeProfitPercent` | `0.15` | 基础输入 0.1–10，单位百分比；新开仓还有短模式限幅 |
| `maxHoldMinutes` | `3` | 整数 1–3，最长持仓退出触发时间 |
| `cooldownSeconds` | `10` | 整数 5–3600，完全平仓后的普通再次入场冷却 |
| `maxBuysPerHour` | `60` | 整数 1–60，滚动一小时的已记录 BUY 上限，含分批加仓 |

所有字段必须存在，数字必须写成 JSON 数字，不能写成带引号的字符串。JSON 不允许注释；未知字段、地址、密钥或可执行代码都会被拒绝。不要把 `0.15` 误读成 15%，这里是 **0.15%**。

先安全停止并核对，再编辑配置；用 `--describe` 检查，然后再明确重启。正在运行的机器人和看板不会自动热加载修改。启动器和看板均在加载本机凭据后应用 JSON，所以 `.env.testnet` 中旧的非秘密策略值不会覆盖它。

持仓的首次入场止损、止盈快照会保留，不因加仓或波动扩大而放宽；但修改最长持仓等规则，仍可能在下次运行时让旧持仓立即满足退出条件。策略/短模式变化需要有意审查迁移，不能靠编辑字段强行接续。

## 八、买卖条件与固定风险规则

### 买入不是定时任务

约每 5 秒检查一次，不保证每 5 秒、每分钟或每 3 分钟成交。网络请求、核对和风控可能让检查更慢。等待有效买入信号没有固定上限。

程序使用已收盘的 1 分钟 EMA 3/8、RSI 7、ATR 7，以及由完整、按 UTC 对齐的 1 分钟组组成的 5 分钟 EMA 3/5 趋势。短动量至少需要 3 个连续报价样本、跨度 10–30 秒；样本间隔超过 15 秒或只读连接失败后重新预热。

两条入场路线都须先满足：价差不超过 0.03%、价格偏离快 EMA 不超过 0.35%、波动成本过滤、剩余额度及入场风控。随后满足其一：

- **趋势延续**：快 EMA 高于慢 EMA、价格在快 EMA 之上，短动量至少 +0.008%，并达到趋势、RSI、成交量等 6 项中的至少 4 分。
- **回调反弹**：已收盘 K 线形成先跌后涨、报价不低于最新收盘价、短动量至少 +0.012%、5 分钟均线偏差不低于 −0.15%，并达到反弹、RSI、成交量等 5 项中的至少 3 分。

信号通过后按 40% / 30% / 30% 分批，默认最多约 40 / 30 / 30 虚拟 USDT。加仓要求仍有入场信号、买一价高于平均买入成本，且中间价较上一批实际成交价至少上涨 0.03%；不下跌摊平。交易所最小数量、最小金额和精度也必须满足。

### 成本与卖出

短模式只读核验测试账户费率，核验有效期 5 分钟，空仓时通常每 60 秒刷新；每笔 BUY 前还会强制重新核验和重新检查报价。无法核验、未知或过期时，每边使用 0.10% 保守费率。额外保留每边 0.02% 滑点假设、实际价差和 0.01% 缓冲。成本未知不会当成零，卖出不依赖费率接口刷新成功。

`4 × ATR 百分比` 必须覆盖估算门槛：核验双边零费率时为 0.05%＋价差，回退费率时为 0.25%＋价差。这只是波动过滤研究指标，**不是预期利润、胜率或已验证优势**。

卖出按可卖出的买一价评估，优先处理冻结止损、冻结止盈和硬超时：

| 规则 | v3 short 行为 |
|---|---|
| 止损 | 首次入场根据基础值与 1.4 × ATR 调整，再限在 0.10–0.40% |
| 止盈 | 根据基础值、2.2 × ATR、成本门槛调整，再限在 0.10–0.60% |
| 最长持仓 | 默认满 3 分钟，下次成功检查时触发退出 |
| 普通信号退出 | 原始开仓至少 10 秒；普通委托间隔至少 5 秒 |
| 软超时 | 满 1 分钟且当前涨幅覆盖估算成本和缓冲时可退出 |
| 移动退出 | 观察到的峰值达到成本门槛再加 0.10% 时启动；回撤距离为 0.8 × ATR，限在 0.08–0.25% |
| 趋势转弱 | 1 分钟与 5 分钟趋势同时转弱，或短动量明显转负并获 EMA / RSI 弱势确认 |

这些是**本机软件触发的退出，不是交易所托管止损单**。停机、休眠、断网、访问受限、数据无效或订单结果不明时都可能延迟，不能承诺 3 分钟一定平仓，也不能保证止损价格。

### 不能通过 JSON 关闭的保护

- 每轮只管理程序有记录的持仓，不把账户获赠或无关 BTC 当成本策略仓位；不可交易的余量另存为自有尘埃记录。
- 亏损后新买入冷却 60 秒；连续 3 次保守风控亏损暂停新买入 15 分钟；按 **UTC 日期**累计的保守已实现风控亏损达到 5 虚拟 USDT 时停止当天新买入。保护性卖出不受这些入场限额阻拦。
- `dailyRisk.realizedUsdt` 是保守风控累积值，不是实际收益报表。真实成交、手续费、已实现盈亏与费用估值是否完整分别记录；未知费用不是零。
- 下单前先保存 pending 客户订单意图；结果不明时先查询核对，绝不盲目重发下单 POST。
- 每轮 100 虚拟 USDT 是累计购买名义金额限制，不是账户总余额上限、市场价值上限或最大亏损保证。

固定评分、分批比例、费率规则、RSI / ATR 周期、采样条件、滑点和亏损保护不是 JSON 可添加的配置项。完整细节见 [交易逻辑参考](VIRTUAL_TRADING_LOGIC.md)与源码。

## 九、停止、断线和恢复

在同一目录的另一个终端执行：

```powershell
npm.cmd run virtual:stop
```

这是安全停止请求，**不自动卖出持仓、不撤销交易所已有订单**。要等待原机器人完成当前操作并退出，再核对其最终状态；发出请求本身不等于已经停止。停止入口不依赖策略或凭据文件有效。

若想停止只读看板，在看板终端按 `Ctrl+C`，不会停止独立的交易进程。前台机器人也处理 `Ctrl+C`，但仍应等待退出和订单核对，不要直接结束进程后立刻开第二个副本。

### 常见问题

| 现象 | 怎么判断 / 处理 |
|---|---|
| 很久没有成交，显示 WAIT | 查看刷新时间、策略检查统计与等待原因；未满足条件不代表死机，不能为了刷成交而去掉成本和风控 |
| 等待连接恢复 / reconnecting | 已确认的只读暂时失败，且没有 pending 时，按 30、60、120、240、300 秒退避，随后最多每 300 秒重试；不是反复下单 |
| 网页打不开 | 看板进程可能没有启动；确认原目录的看板终端与端口，不能因此再启动第二个机器人 |
| 网页能开但连接失败 | 本地页面可用不代表测试网 API 可用；查看错误和时间，旧余额不是当前余额 |
| 3001 端口已占用 | 可能已有看板；先检查现有服务，不要随意结束未知进程 |
| 只有读取权限、签名失败或权限错误 | 在测试网核对 API Key、配对私钥 / Secret 和必要交易权限；不需要提现权限，不能用主站凭据替换 |
| HTTP 451 或明确地区 / 来源拒绝 | 停止并核实服务资格或联系 Binance；不换主机、代理或 API 来绕过限制 |
| HTTP 429 / 418 限流 | 停止排查请求来源与平台限制；不要并开多个副本或重发委托 |
| 提示已有锁、账户 / 策略不匹配 | 先核对原进程、账户和记录，不删除锁或状态来强行启动 |
| 显示 pending、订单结果不明 | 保留客户端订单号，以测试网查询核对结果；不得直接补一笔“相同订单” |
| EPERM / EACCES / EBUSY 保存失败 | 程序只对本机文件替换做有限重试，绝不借此重发订单；保留原状态与失败临时文件，停止后审查权限、占用和订单 |

只读网络重连期间即使心跳仍更新，**也不表示能够平仓**。若有持仓，断线期间本机保护无法保证执行；恢复后可能因超时立即卖出。明确访问拒绝、权限异常、限流、无效数据、订单 POST 失败或存在未知结果，不适用自动只读重连。

只读看板会锁存明确的地区 / 来源拒绝。应先核实合法访问确实恢复，再由操作者重启看板；不能用反复重启规避服务限制。

### 原电脑续用与迁移

安全恢复清单：

1. 确认原机器人是否真的退出；区分“等待信号”“正在重连”“已停止”。只重启看板不需要重启机器人。
2. 保留 `.paper-data/testnet-state.json`、心跳、pending、客户端订单号、所有尘埃和失败临时文件。不要清零亏损计数或重建空仓来增加频率。
3. 如需维修或迁移，先停止并确认退出，安全备份整个运行记录与本机凭据。凭据备份单独保管，不上传 Git 或源码包。
4. 与测试网核对已成交、未完成订单及本程序自有数量。未解决的订单结果必须先核对，不能靠删记录跳过。
5. 同账户、同策略、同目录的记录核对无误后，才再次运行第五节中的明确启动命令；程序重新采样，不补做错过的历史信号。

第 5 步所指启动命令为：

```powershell
npm.cmd run virtual:run -- --enable-testnet-orders
```

若换目录或电脑，不要简单把 ZIP 解压后沿用同一账户启动。应在原实例确定停止、订单已核对后，受控迁移完整原状态和适配的凭据，保持唯一执行者；本包不提供自动账户迁移。

`npm.cmd run virtual:adopt` 是**显式离线记录迁移**工具，不是常规启动或恢复按钮。它要求原账户身份、已停止的兼容记录和本地独占锁，保留持仓、尘埃与订单，并将迁入旧持仓标为只退出、不再加仓；它不卖出、不联网、不自动开机。不能用于掩盖 pending、账户错配、缺失所有权或测试网重置。不要未经审查运行它。

需要再次导出干净源码时，在程序根目录执行：

```powershell
node scripts/package-virtual.mjs --check
node scripts/package-virtual.mjs
```

结果是 `exports` 内带时间戳的 ZIP、`.sha256` 与 `.manifest.json`，不覆盖以前的包。打包器只读取明确列出的源码和空白模板，清空导出模板里的凭据字段；不读取实际 `.env.testnet`、私钥、账户记录或日志，不联网、不启动交易、不推送 GitHub。

在 GitHub 保存或分发时，上传审查后的干净源码；不要把原运行目录整体上传。随包 `.gitignore` 排除实际环境文件、`.secrets`、`.paper-data`、PEM、日志等，但**忽略规则无法撤回以前已经提交的秘密**。不要把含账户信息的日志、截图或运行记录加到仓库、Issue、Release。

GitHub 仓库只托管源码，并不会让机器人持续运行。此包不创建开机启动项、计划任务、守护服务或常驻云任务，不更改系统电源设置；保持电脑醒着、联网和终端存活仍由操作者负责。不要把它当作关机后仍受保护的交易系统。
